## 🎨 Scene Design

### Objects in Scene

1. **Ground** (GroundMesh)
   - Massive terrain (102400 x 20000 units)
   - PBR material with tiled albedo texture
   - Position: Origin

2. **Sky** (Mesh)
   - Procedural skybox (SkyMaterial)
   - Scaled 100x
   - Realistic atmospheric scattering

3. **chatBackground** (Plane)
   - Frame/border for chat interface
   - Dark reddish-brown (#6F3838)
   - Position: [0, -12.26, 424.93]
   - Scaling: [5, 3.5, 1]

4. **chatScreen** (Plane)
   - Interactive chat surface
   - Light purple-blue (#6A6AAF)
   - 20% opacity (transparent)
   - Position: [0, 0, 375.33]
   - Scaling: [4, 3, 1]

### Visual Design

**Color Strategy**:
- Warm brown frame + cool blue screen = visual hierarchy
- Semi-transparent screen = environmental awareness
- Matte materials = VR comfort

**Layout**:
- Chat panels ~400 units in front of camera
- Layered design (screen 50 units in front of background)
- Eye-level positioning (Y: ~0 to -12)

## ⚠️ Important Notes

### Why We Reset

**Problems with Previous Approach**:
- Started with code before scene design
- Constant build/cache issues
- Mixing manual code with editor exports
- Unclear which camera/scene to use

**Benefits of Editor-First**:
- Visual design comes first
- Single source of truth (editor scene)
- Cleaner code generation
- Easier to iterate

### What NOT to Do

❌ **Don't** manually create Babylon.js objects in code  
❌ **Don't** modify files in `public/scene/` (generated by editor)  
❌ **Don't** mix editor exports with manual scene setup  
❌ **Don't** install old dependencies from previous branch  

### What TO Do

✅ **Do** design everything in Babylon Editor first  
✅ **Do** export from editor, then integrate  
✅ **Do** write scripts for behavior (not scene structure)  
✅ **Do** keep editor as source of truth

## 🔧 Development Workflow

### Recommended Process

```
1. Design in Babylon Editor
   ↓
2. Export scene to public/scene/
   ↓
3. Load scene in Next.js
   ↓
4. Test rendering
   ↓
5. Add GUI overlays
   ↓
6. Attach script components
   ↓
7. Implement interactivity
   ↓
8. Test in VR
   ↓
9. Iterate (back to step 1 if needed)
```

### Testing Strategy

**Desktop Testing**:
1. Run `npm run dev`
2. Open http://localhost:3000
3. Verify scene loads
4. Test mouse/keyboard interaction

**VR Testing**:
1. Run `npm run dev` with network binding
2. Access from VR headset browser
3. Enter VR mode
4. Test controller interaction

## 🎓 Lessons Learned

### Key Insights

1. **Editor-First is Essential**
   - Visual design should come before code
   - Editor is the source of truth
   - Exports should not be manually modified

2. **Clean Slate Approach**
   - Sometimes starting over is faster
   - Remove accumulated technical debt
   - Clear separation of concerns

3. **Documentation Matters**
   - Design specs prevent confusion
   - Handoff docs ensure continuity
   - Reference materials speed up development

4. **Material Design is Important**
   - Colors affect usability
   - Transparency helps VR comfort
   - Matte surfaces reduce eye strain
