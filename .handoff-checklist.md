# Handoff Preparation Checklist

**For AI Assistant: Critical Steps When Preparing Project Handoff**

## ⚠️ IMPORTANT: Synchronization Requirements

When preparing a handoff document, ALWAYS synchronize:

### 1. GitHub Issues with Local Documentation ✅ CRITICAL

**Before creating handoff:**

- [ ] Create GitHub issues from detailed specs (GITHUB_ISSUES.md)
- [ ] Update GITHUB_ISSUES.md with:
  - ✅ Creation status
  - 🔗 Links to actual GitHub issues
  - 📅 Creation dates
- [ ] Update PRIORITIZED_TASKS.md with:
  - Issue numbers from GitHub
  - Current status of each task
  - Dependencies on actual issue numbers

**Files to Synchronize:**
```
GITHUB_ISSUES.md ←→ GitHub Repository Issues
       ↓
PRIORITIZED_TASKS.md (reference issue #s)
       ↓
HANDOFF.md (link to both)
```

### 2. Documentation Cross-References

- [ ] Ensure all documentation links are valid
- [ ] Update INDEX.md if new docs added
- [ ] Verify all relative paths work
- [ ] Check external links still valid

### 3. Project Status Updates

- [ ] Update version numbers across files
- [ ] Sync milestone information
- [ ] Update completion percentages
- [ ] Verify effort estimates current

## Handoff Document Must Include

### Core Sections
- [ ] Executive summary
- [ ] What was delivered
- [ ] Current project status
- [ ] Immediate next steps
- [ ] Critical success factors
- [ ] Risk assessment
- [ ] Documentation guide
- [ ] **Synchronization status** ⚠️

### Verification Checklist
- [ ] All GitHub issues created
- [ ] Issue links working
- [ ] Task priorities match GitHub labels
- [ ] Dependencies correctly mapped
- [ ] Milestones aligned

## Common Mistakes to Avoid

❌ Creating handoff BEFORE synchronizing GitHub issues  
❌ Leaving "To Be Created" status without updating  
❌ Forgetting to link GITHUB_ISSUES.md to actual issues  
❌ Not updating PRIORITIZED_TASKS.md with issue numbers  
❌ Missing cross-references between documents  

## Template Synchronization Workflow

```
1. Prepare detailed issue descriptions
   ↓
2. Create GitHub issues (via gh CLI or script)
   ↓
3. Update GITHUB_ISSUES.md with ✅ and links
   ↓
4. Update PRIORITIZED_TASKS.md with issue #s
   ↓
5. Update HANDOFF.md with current status
   ↓
6. Verify all links work
   ↓
7. Create handoff summary
```

## Quick Verification Commands

```bash
# List created issues
gh issue list --json number,title,labels

# Verify issue count
gh issue list --json number | jq length

# Check specific priority
gh issue list --label "critical" --json number,title

# Verify all links in markdown
# (Use markdown link checker tool)
```

## Files Requiring Synchronization

| File | Updates Needed | Timing |
|------|----------------|--------|
| GITHUB_ISSUES.md | Status, links | After issue creation |
| PRIORITIZED_TASKS.md | Issue numbers | After issue creation |
| HANDOFF.md | Status, checklist | During handoff |
| README.md | Links, status | During handoff |
| specs/INDEX.md | New docs | When docs added |

## Best Practices

### Timing
- Create issues FIRST
- Synchronize docs IMMEDIATELY after
- Prepare handoff LAST

### Documentation
- Use ✅ for completed items
- Use 🔗 for active links
- Use ⚠️ for important notes
- Use 📋 for pending items

### Quality Checks
- Click every link
- Verify issue numbers match
- Check labels are correct
- Ensure priorities align
